## Description

As the ShadowFeed content engine, I need the discovery pipeline upgraded from title-only fetching to full article body scraping + LLM summarization, so that generated content uses REAL data and statistics instead of LLM-fabricated content.

The current v1 discovery only captures article titles. The v2 pipeline adds two critical stages: Stage 4 (body scraping via Puppeteer) and Stage 5 (LLM summarization into a structured ResearchDigest). This transforms generated content from shallow to data-backed.

## Tasks

### Task 1 — Create Winner Scraper (AC: 1, 7)

Create `src/modules/forge-shadowfeed/discovery/shadowfeed-winner-scraper.ts`:

- Import and reuse `scrapeBlogUrl()` from `src/modules/manual-news/url-scraper.ts`
- Same pattern as `src/modules/forge-smart/smart-winner-scraper.ts`
- Source-specific handling:
  - Google News / Blogs: Puppeteer → extract `<article>` or `<main>` body → 4000 chars max
  - Twitter: use thread content already fetched (skip scrape)
  - Reddit: use `.json` API for full selftext
- Return: `{ scrapedBody: string; charCount: number; source: string }` or `null` on failure
- Graceful fallback: scrape failure NEVER breaks pipeline, logs warning and returns null

- [x] Implemented

### Task 2 — Create Content Summarizer (AC: 2)

Create `src/modules/forge-shadowfeed/discovery/shadowfeed-content-summarizer.ts`:

- Takes scraped body text + pillar context as input
- Calls gpt-4o-mini to extract structured ResearchDigest:
  - `keyInsight`: 1-sentence core takeaway
  - `dataPoints[]`: Concrete numbers from article (NEVER invented)
  - `provocativeAngle`: How to frame as wake-up-slap
  - `educationalAngle`: How to frame as educational
  - `brandMentions[]`: Companies/tools detected
  - `quotableLines[]`: 2-3 lines usable as slide headlines
  - `contentDepth`: shallow/medium/deep
  - `rawBody`: Original scraped text (up to 3000 chars)
- Failure returns `null` (fallback to title-only discovery)

- [x] Implemented

### Task 3 — Create Discovery Service Orchestrator (AC: 3)

Create `src/modules/forge-shadowfeed/discovery/shadowfeed-discovery.service.ts`:

6-stage sequential pipeline:
```
Stage 1: QUERY GEN → pillar-specific queries (existing)
Stage 2: MULTI-FETCH → Google News BR + Reddit BR + Twitter BR (existing)
Stage 3: SCORE → pillar-weighted scoring → select winner (existing)
Stage 4: SCRAPE → winner body extraction (NEW - Task 1)
Stage 5: SUMMARIZE → LLM extracts ResearchDigest (NEW - Task 2)
Stage 6: RETURN → DiscoveryResult or DiscoveryFailure
```

- Returns `{ digest: ResearchDigest, discoverySource: DiscoverySource }` on success
- Returns `{ reason: string }` on failure → service falls back to template

- [x] Implemented

### Task 4 — Update Prompt Builder Block 4 (AC: 4, 5)

Update `src/modules/forge-shadowfeed/shadowfeed-prompt-builder.ts`:

- When `PromptSource.type === 'research'`:
  - Include key insight (1 sentence)
  - Include ALL extracted data points with instruction "USE these — do NOT invent"
  - Include angle suggestion based on active pillar
  - Include quotable lines as headline inspiration
  - Include full article body for context depth
- Existing `discovery` and `template` types remain unchanged

- [x] Implemented

### Task 5 — Integrate Discovery v2 into Service (AC: 3, 6)

Update `forge-shadowfeed.service.ts`:
- Replace direct query→fetch→score calls with `shadowfeed-discovery.service.ts` orchestrator
- On discovery success with ResearchDigest: use `{ type: 'research' }` PromptSource
- On discovery failure: fall back to template selection (existing behavior)

- [x] Implemented

### Task 6 — Typecheck & Test (AC: 7)

- Run `npm run typecheck` — clean
- Manual test: generate 10 posts with discovery, verify >70% have scraped_body >200 chars
- Verify no regressions in existing generation pipeline

- [x] Implemented

## Risks

| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| Scraper blocked by news sites (anti-bot, paywall) | Medium | Medium — reduced content depth for blocked articles | Graceful fallback to title+snippet (same as v1); never breaks pipeline (AC6) |
| Puppeteer timeout on slow/heavy pages | Medium | Low — single post affected, not batch | Set 10s timeout per scrape; on timeout return null and fall back to template |
| LLM summarizer produces low-quality ResearchDigest | Low | Medium — generated content lacks depth | Use structured JSON output mode with gpt-4o-mini; validate dataPoints[] is non-empty |
| Extra LLM cost from summarizer calls | Low | Low — ~$0.014/day max | gpt-4o-mini is cheap; max 7 discovery posts/day (PRD §13) |
