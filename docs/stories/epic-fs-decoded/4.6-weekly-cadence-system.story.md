## Description

As the ShadowFeed content engine, I need a weekly cadence system that maps each day of the week to a specific pillar and funnel tier, so that `generateBatch()` follows the BrandsDecoded weekly rhythm instead of cycling through all pillars every day.

The current v1 generates one post per pillar every batch. The v2 cadence system assigns specific pillars to specific days based on Research §09 (audience behavior by day of week). This creates strategic weekly rhythm: education on Mon/Tue, provocation on Wed, analysis on Thu, proof on Fri, offers on Sat, light value on Sun.

## Tasks

### Task 1 — Implement Weekly Cadence Module (AC: 1)

Create `src/modules/forge-shadowfeed/shadowfeed-weekly-cadence.ts`:

Day-of-week mapping from PRD §5 FR-CAD:

| Day | dayOfWeek (0=Sun) | Primary Pillar | Funnel Tier | Preferred Hook Archetypes |
|---|---|---|---|---|
| Sunday | 0 | `educational-value` (light, 4-6 slides) | top | `curiosity-mystery`, `specific-number` |
| Monday | 1 | `educational-value` | top | `specific-number`, `direct-controversy` |
| Tuesday | 2 | `educational-value` | top | `specific-number`, `transformative-promise` |
| Wednesday | 3 | `wake-up-slap` | top | `polarization`, `direct-controversy` |
| Thursday | 4 | `brand-breakdown` | top | `brand-comparison`, `curiosity-mystery` |
| Friday | 5 | `proof-social` | middle | `transformative-promise`, `specific-number` |
| Saturday | 6 | `the-offer` | bottom | `direct-controversy`, `transformative-promise` |

```typescript
interface CadenceEntry {
  dayOfWeek: number; // 0-6
  dayName: string;
  pillarId: PillarId;
  funnelTier: FunnelTier;
  preferredHookArchetypes: HookArchetype[];
  isLightContent: boolean; // Sunday = true
}

function getTodayCadence(): CadenceEntry
function getWeeklyCadence(): CadenceEntry[]
function getCadenceForDate(date: Date): CadenceEntry
```

- [x] Implemented

### Task 2 — Update generateBatch() (AC: 2)

Update `forge-shadowfeed.service.ts` → `generateBatch()`:

**Old behavior (v1):** Loop through all active pillars, generate 1 post per pillar
**New behavior (v2):**
1. Get today's cadence entry → determine pillar
2. Generate 1 post for today's pillar
3. Use cadence's preferred hook archetypes for archetype selection boost
4. Sunday: override slide range to 4-6 (light content)
5. Save cadence record to `sf_shadowfeed_cadence` table

- [x] Implemented

### Task 4 — Track Cadence History (AC: 3)

After each generation, insert record into `sf_shadowfeed_cadence`:

```sql
INSERT INTO sf_shadowfeed_cadence (
  week_start, day_of_week, pillar_id, hook_archetype,
  funnel_tier, queue_item_id
) VALUES (
  date_trunc('week', now()), extract(dow from now()),
  $pillarId, $hookArchetype, $funnelTier, $queueItemId
)
```

- `week_start` = Monday of current week
- Links to queue item via `queue_item_id` FK

## Risks

| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| Batch behavior change (1 post/day vs multi-pillar) surprises admin team | Medium | Medium — admin expects multiple posts per batch | Document behavior change in API response; admin dashboard shows "today's pillar" context |
| Timezone handling for day-of-week mapping | Medium | Medium — wrong pillar if server timezone differs from target audience | Use account's configured timezone (or BRT default) for day-of-week calculation |
| No override mechanism for special occasions (holidays, launches) | Low | Low — can still use `generate/:pillarId` endpoint for manual override | `generate/:pillarId` endpoint remains available for ad-hoc generation outside cadence |
| Cadence table unique constraint blocks re-generation for same day | Low | Medium — cannot regenerate if first attempt fails | Handle constraint violation gracefully (upsert or delete+insert) |

## Dev Notes

### Current Batch Generation (v1)
- `generateBatch()` loops through all active pillars (4 posts/batch)
- No day-of-week awareness
- v2 changes to 1 post/day based on cadence
- [Source: PRD §1.2 — "Same 4 pillars every day"]

### Sunday Light Content
- Sunday uses `educational-value` pillar but with reduced slide count (4-6 instead of 8-12)
- Pass `isLightContent: true` flag to override pillar's default slide range
- [Source: PRD §5 FR-CAD-05 — "post de valor leve (3-5 slides)"]

### Cadence Table
- Created by FSD-01 migration (`sf_shadowfeed_cadence`)
- Unique constraint on `(week_start, day_of_week, pillar_id)` — one record per day per week
- [Source: PRD §9.1]

### Integration Points
- Uses `HookArchetype` type from FSD-01
- Uses `FunnelTier` type from FSD-01
- Preferred archetypes boost weight in FSD-04's selection function
- Funnel tier auto-assigned per FSD-05's mapping
