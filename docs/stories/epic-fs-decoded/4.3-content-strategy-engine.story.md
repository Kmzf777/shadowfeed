## Description

As the ShadowFeed content engine, I need the persona rewritten with BrandsDecoded-inspired voice rules, a 3-phase copy progression system (interruption → development → conversion), contextual CTAs per pillar, the content validator updated with new slide roles (context, tension, soft-cta), and few-shot examples rewritten for all 5 pillars, so that generated carousels follow the exact copy strategy that made @brandsdecoded__ successful.

This story rewrites the prompt builder's structure blocks, the persona definition, the content validator, and creates new few-shot examples. It transforms how the LLM generates copy — from generic to strategically phased.

## Tasks

### Task 1 — Rewrite Persona (AC: 1)

Rewrite `src/modules/forge-shadowfeed/shadowfeed-persona.ts`:

Key changes from v1 (per PRD §8.4):
- **Identity**: AI that IS the proof of the product (Research §11 Diferencial 1)
- **Copy style**: Direct, no hedging, sometimes brutal (Research §11 Diferencial 4)
- **Anti-patterns**: No guru-speak ("segredo que ninguém conta"), no motivation ("jornada"), no begging engagement
- **NEW rule**: "O cover AFIRMA. Nunca pergunta." (Research §06)
- **NEW rule**: 3-phase copy progression instruction (Research §07)
- **No-euphemism rule**: Anti-patterns list — no "talvez", "pode ser", no corporate tone

- [x] Implemented

### Task 2 — Rewrite Prompt Builder with 9-Block Structure (AC: 2, 3)

Rewrite `src/modules/forge-shadowfeed/shadowfeed-prompt-builder.ts`:

9-block prompt assembly (per PRD §6.3):
```
Block 1: Persona (from Task 1)
Block 2: Pillar rules (slide count, content type, engagement objective)
Block 3: Copy phase rules (interruption/development/conversion)
Block 4: Source/Research data (from FSD-02, or template)
Block 5: Hook archetype (placeholder for FSD-04)
Block 6: Double door seed (placeholder for FSD-05)
Block 7: Product context (ShadowFeed info)
Block 8: Anti-patterns (what NOT to do)
Block 9: Output format (JSON structure with slide roles)
```

- Block 3 (Copy Phases) per PRD §5 FR-COPY:
  - **Phase 1 — Interruption** (slides 1-2): Zero explanation, only tension. Techniques: numeric shock, polarizing statement, taboo word, identity denial
  - **Phase 2 — Development** (slides 3-N): Title + 2-4 lines per slide. Direct language. Transition phrases ("→ Mais no próximo")
  - **Phase 3 — Conversion** (final slides): Contextual CTA based on pillar

- Block 2 includes CTA mapping per pillar (from PRD §4.4)

- [x] Implemented

### Task 3 — Update Content Validator (AC: 4)

Update content validation logic to accept the 7-zone carousel anatomy:

New allowed roles per PRD §8.5:
| Zone | Role | Validation Rule |
|---|---|---|
| Slide 1 | `hook` | MUST be first slide |
| Slides 2-3 | `context` | SHOULD follow hook (warning if missing) |
| Slides 4-N | `content` | Main body slides |
| Antepenultimate | `tension` | SHOULD be present (warning if missing) |
| Penultimate | `soft-cta` | SHOULD be present (warning if missing) |
| Last | `cta` | MUST be last slide |

- Slide 1: role MUST be `hook` (error if not)
- Last slide: role MUST be `cta` (error if not)
- Context/tension/soft-cta: SHOULD be present (warning, not error)

- [x] Implemented

## Risks

| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| LLM does not consistently follow new persona rules (drifts to generic tone) | Medium | Medium — generated content sounds like v1, not Decoded | Reinforce rules in anti-patterns block (Block 8); add few-shot examples that demonstrate correct tone |
| Few-shot examples quality determines output quality | High | HIGH — poor examples produce poor content | Author few-shots from actual @brandsdecoded__ post analysis; review with product team before merge |
| Content validator strictness may reject valid LLM output | Medium | Medium — increased generation failures | Use SHOULD (warning) for context/tension/soft-cta roles, MUST (error) only for hook and cta positions |
| 9-block prompt becomes too long, exceeding token limits | Low | Medium — prompt truncation degrades output | Monitor total prompt token count; keep blocks concise; use gpt-4.1 with 128K context |
