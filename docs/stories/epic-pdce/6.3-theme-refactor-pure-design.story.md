## Description

As the content engine, I need themes to be pure visual design configurations with zero influence on content logic, slide count, or density, so that adding new themes requires only visual configuration and content strategy is fully driven by pillars.

This story strips content-logic fields from `PostTheme`, migrates them to `PillarConfig`, updates the theme-applier and frontend renderer to use `layoutMap` with universal `SlideRole`, and ensures existing posts render correctly.

## Technical Notes

- Fields migrated FROM themes TO pillar configs: `slideCount` → `PillarConfig.slideRange`, `contentDensity` → derived from `content_depth` setup field, `emojiUsage` → derived from `brand_personality`, `systemPromptKey` → `PillarConfig.objective`, `toneInstructions` → `PillarConfig.toneOverride`
- The `layoutMap` provides the bridge: themes say HOW to display each role, pillars say WHICH roles exist and in what order
