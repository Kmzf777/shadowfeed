## Description

As the content engine, I need Forge Smart's content scoring to use pillar-specific scoring weights and source weight multipliers, so that the same set of content candidates ranks differently depending on the selected pillar (e.g., PROVOKE favors recency and Twitter, EDUCATE favors richness and Google News).

---

## Acceptance Criteria

- [x] **AC1** — Content scoring uses `pillarConfig.scoringWeights` instead of the fixed `(0.40, 0.30, 0.20, 0.10)` weights
- [x] **AC2** — After calculating `final_score`, source weight multiplier is applied: `adjustedScore = final_score * pillarConfig.sourceWeights[candidate.source_type]`
- [x] **AC3** — Same candidates score differently per pillar (testable with unit test)
- [x] **AC4** — Source weight multipliers correctly boost/penalize sources per pillar config (e.g., Twitter 1.5x for PROVOKE, Reddit 1.5x for CONNECT)

## Tasks

### Task 1 — Apply Pillar Scoring Weights (AC: 1)

Update the scorer in Forge Smart service:

```typescript
const { recency, engagement, relevance, richness } = pillarConfig.scoringWeights;
const score = (recencyScore * recency) + (engagementScore * engagement)
            + (relevanceScore * relevance) + (richnessScore * richness);
```

### Task 2 — Apply Source Weight Multipliers (AC: 2, 4)

After calculating `final_score`:

```typescript
const adjustedScore = candidate.final_score * pillarConfig.sourceWeights[candidate.source_type];
```

### Task 3 — Tests (AC: 3)

Create test that:
1. Given the same 5 candidates
2. Score them with EDUCATE weights vs PROVOKE weights
3. Assert different ranking order
4. Assert source multipliers change relative positions
