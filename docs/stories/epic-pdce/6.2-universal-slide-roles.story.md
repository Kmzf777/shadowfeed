## Description

As the content engine, I need a single universal `SlideRole` enum (`hook | context | content | tension | soft-cta | cta`) used across ALL generation methods (personalized, smart, shadowfeed), so that themes can map roles to layouts uniformly and the content schema is consistent.

This story unifies the existing role enums, updates the Zod content validation schema, and ensures backward compatibility with existing posts.

---

## Acceptance Criteria

- [ ] **AC1** — A single `SlideRole` type (`'hook' | 'context' | 'content' | 'tension' | 'soft-cta' | 'cta'`) is the canonical role type used in `content-schema.ts`
- [ ] **AC2** — The Zod validation schema in `content-schema.ts` accepts only universal roles for new posts
- [ ] **AC3** — The `content-validator.ts` handles backward compatibility: existing posts with legacy role values (e.g. theme-specific roles) pass validation with a mapping to universal roles
- [ ] **AC4** — The `SlideRole` type from `pillar.types.ts` (PDCE-01) is re-exported from `content-schema.ts` as the single source of truth
- [ ] **AC5** — All existing tests pass; new tests verify role mapping and validation
