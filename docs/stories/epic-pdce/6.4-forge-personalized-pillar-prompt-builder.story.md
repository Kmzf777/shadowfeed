## Description

As the content engine, I need the Forge Personalized prompt builder to evolve from 9 blocks to 10 blocks with a dedicated PILLAR RULES block, dynamic persona generation from Setup V2, and awareness-level calibration, so that every user-generated post is strategically driven by the selected pillar and deeply personalized from their profile data.

This is the largest story in the epic — it transforms the core prompt architecture to be pillar-aware.

---

## Acceptance Criteria

- [ ] **AC1** — `ForgePersonalizedRequest` accepts an optional `pillarId` field; defaults to `'educate'` when not provided
- [ ] **AC2** — The prompt builder generates a 10-block prompt per PRD §7.1: PERSONA, PILLAR RULES, AUDIENCE CONTEXT, COPY PHASES, SOURCE DOCUMENT, HOOK ARCHETYPE, PRODUCT SEED, ANTI-PATTERNS, AWARENESS CALIBRATION, OUTPUT FORMAT
- [ ] **AC3** — Block 1 (PERSONA) is dynamically generated from Setup V2 fields: `brand_personality`, `voice_tone`, `expertise_statement`, `niche`
- [ ] **AC4** — Block 2 (PILLAR RULES) includes the pillar's `objective`, `requiredElements`, `forbiddenElements`, `toneOverride`, `ctaStyle`, `captionStyle`, and `slideRange`
- [ ] **AC5** — Block 3 (AUDIENCE CONTEXT) uses `target_audience`, `audience_frustration`, `audience_desire`, `audience_objection`, `audience_awareness`
- [ ] **AC6** — Block 9 (AWARENESS CALIBRATION) adapts hook strategy, content depth, and CTA directness per awareness level per PRD §12
- [ ] **AC7** — The `slideRange` is determined by `PillarConfig.slideRange`, NOT by the theme
- [ ] **AC8** — Setup V2 field mapping matches PRD §7.2 — all listed fields are used in their designated blocks
- [ ] **AC9** — The LLM output JSON includes `pillar_id` field for tracking
- [ ] **AC10** — Graceful fallbacks: when Setup V2 fields are null, prompts use generic niche-appropriate defaults
