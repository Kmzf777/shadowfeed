## Description

As a ShadowFeed user in Auto mode, I need the /create page to show a discovery progress indicator followed by 3 curated source options (plus a custom URL fallback), so that I can choose the best source for my pillar-driven post instead of blindly accepting a single auto-selected article.

---

## Acceptance Criteria

- [x] **AC1** — A new `POST /api/forge-smart/discover` endpoint returns top 3 scored candidates per PRD §16.3
- [x] **AC2** — The discovery endpoint returns: `candidates[]` (title, summary, url, source_type, final_score, posted_at), `queriesUsed[]`, `pillarId`
- [x] **AC3** — In Auto mode, after pillar selection, a loading state shows: "Searching {niche} content for {pillar}..."
- [x] **AC4** — After discovery completes, 3 candidate cards are displayed with: title, score, source type icon, time ago
- [x] **AC5** — A "Paste a custom URL instead" option is available below the 3 candidates
- [x] **AC6** — When user selects a curated source, Forge Smart enriches it (scrapes body) then delegates to Forge Personalized for generation
- [x] **AC7** — The discovery results follow existing design system: dark theme, glass morphism, border-white/10

## Tasks

### Task 1 — Discovery Endpoint (AC: 1, 2)

Create `POST /api/forge-smart/discover` in Smart controller:

Request:
```typescript
{ userId: string; pillarId: PillarId }
```

Response:
```typescript
{
  candidates: Array<{
    title: string;
    summary: string | null;
    url: string | null;
    source_type: SourceType;
    final_score: number;
    posted_at: string | null;
  }>;
  queriesUsed: string[];
  pillarId: PillarId;
}
```

Service logic:
1. Get user Setup V2 data
2. Get pillar config
3. Run pillar-specific query generation (from PDCE-06)
4. Score candidates with pillar weights (from PDCE-07)
5. Return top 3

### Task 2 — Discovery Loading State (AC: 3)

Create `web/src/app/create/components/DiscoveryProgress.tsx`:
- Shows animated progress indicator
- Text: "Searching {niche} content for {pillar}..."
- Appears after pillar selection in Auto mode
- Transitions to candidate cards when API responds

### Task 3 — Candidate Cards (AC: 4, 5, 7)

Create `web/src/app/create/components/DiscoveryCandidates.tsx`:
- 3 candidate cards showing: title, score badge, source type icon, time ago
- Each card is selectable
- Below cards: "Paste a custom URL instead" link/button that reveals URL input
- Design: dark theme, glass morphism, border-white/10, rounded-[3px]

### Task 4 — Source Enrichment & Generation Flow (AC: 6)

When user selects a curated source:
1. Send selected candidate URL to enrichment (body scraping)
2. Pass enriched content + `pillarId` to Forge Personalized generate
3. Show generation progress as normal

When user uses custom URL:
1. Use standard manual mode flow with the URL
2. Include `pillarId` from pillar selection step
