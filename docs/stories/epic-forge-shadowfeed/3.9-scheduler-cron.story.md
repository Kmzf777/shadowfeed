## Description

As an admin, I need an automated scheduler that checks for approved posts whose scheduled time has arrived and triggers the Playwright publisher to post them to Instagram, so that the 4-pillar daily schedule runs autonomously at the correct BRT times (09:00, 13:00, 17:00, 20:00).

The scheduler uses Supabase pg_cron (primary) or Vercel Cron Jobs (fallback) to trigger a webhook that checks the queue and publishes.

### Task 2 — Create publish-check webhook endpoint

`POST /api/forge-shadowfeed/publish-check`
- Protected endpoint (admin token or internal secret)
- Calls `scheduler.checkAndPublish()`
- Returns count of published/failed items

### Task 3 — Implement sequential publishing

Process due items one at a time:
1. Set status → `posting`
2. Call `publisherService.publishPost(item)`
3. On success: status → `posted`
4. On failure: status → `failed`, record error
5. Wait 30–60 seconds between posts (anti-detection)

### Task 4 — Create Supabase pg_cron migration

```sql
SELECT cron.schedule(
  'shadowfeed-publish-check',
  '* * * * *',
  $$
    SELECT net.http_post(
      url := current_setting('app.settings.shadowfeed_publish_webhook'),
      body := '{}'::jsonb
    )
  $$
);
```

### Task 5 — Create Vercel cron fallback config

```json
// vercel.json addition
{
  "crons": [{
    "path": "/api/forge-shadowfeed/publish-check",
    "schedule": "* * * * *"
  }]
}
```

### Task 6 — Implement double-posting prevention

Use atomic status update:
```sql
UPDATE sf_shadowfeed_queue
SET status = 'posting', updated_at = NOW()
WHERE id = $1 AND status = 'approved'
RETURNING *
```
If no rows returned → already being processed.

## Dev Notes

### Timezone

All time comparisons must use `America/Sao_Paulo` (BRT/BRST). The scheduled times (09:00, 13:00, 17:00, 20:00) are in BRT.

### Rate Limiting

Even though we check every minute, we only publish max 4 posts/day. The 30–60 second delay between posts is an additional safety measure.

### Cron Choice

Supabase pg_cron is preferred but requires `pg_net` extension for HTTP calls. If not available, use Vercel Cron Jobs. Document both options.
