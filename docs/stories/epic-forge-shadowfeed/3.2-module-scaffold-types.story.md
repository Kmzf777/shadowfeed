## Description

As a developer, I need the `forge-shadowfeed` module scaffolded with its TypeScript types, controller with all API route stubs, service skeleton, and environment configuration, so that parallel story development (templates, discovery, theme, prompt builder) can proceed against stable interfaces.

This story creates the empty module structure, all types/interfaces, controller with route definitions, and env config — but does NOT implement business logic (that's stories 3.3–3.6).

## Dev Notes

### Admin Token Security

The middleware returns HTTP 404 (not 401) when token is invalid — this hides the existence of the admin panel. Token is checked via `x-sf-admin-token` header or `?token=` query param.

### Service Method Stubs

All service methods should have proper TypeScript signatures with return types, but throw `new Error('Not implemented')` in their body. This lets other stories implement against stable interfaces.

### Pillar Constants

Define the 4 pillars as a constant array with their configs:
- `wake-up-slap`: 09:00, 5-8 slides, controversy/opinion, 80% hardcoded
- `proof-of-machine`: 13:00, 7-10 slides, authority, 100% hardcoded
- `shadow-school`: 17:00, 8-12 slides, educational, 70% discovery
- `the-offer`: 20:00, 5-8 slides, sales, 50% discovery
