## Description

As an admin of the ShadowFeed system, I need the batch generation orchestrator and all queue/approval API endpoints implemented, so that I can trigger generation of the next day's 4 posts, review them, approve/edit captions, and manage the publishing queue.

This story implements the `forge-shadowfeed.service.ts` business logic and wires up all controller route handlers from their 501 stubs to real implementations.

## Tasks

### Task 1 — Implement generateBatch()

Orchestrator flow per spec § 10:
```
For each active pillar:
  1. Check if 100% hardcoded → select template
  2. Else → run discovery engine (query → fetch → score)
  3. If discovery returns null → fallback to template
  4. Build prompt (via prompt builder)
  5. Generate carousel (LLM call)
  6. Save to sf_posts
  7. Create queue item in sf_shadowfeed_queue
  8. Log generation_time_ms
```

### Task 2 — Implement generatePillar()

Same as batch but for a single pillar ID.

### Task 3 — Implement queue query endpoints

- `getQueue(date)` → query `sf_shadowfeed_queue` by date, join with `sf_posts` for post data
- `getRecentPosts()` → last 7 days, ordered by date desc

### Task 4 — Implement approval endpoints

- `approvePost(id)` → set status `ready` → `approved`
- `updateCaption(id, newCaption)` → update caption on associated `sf_posts` record
- `publishNow(id)` → set status → `posting`, trigger publisher (if available)

### Task 5 — Implement config endpoints

- `getConfig()` → read singleton from `sf_shadowfeed_config`
- `updateConfig(data)` → update `publish_enabled`, `pillars`, `theme_brand_ratio`

### Task 6 — Implement stats endpoint

Basic metrics:
- Posts generated today
- Total posts generated
- Average generation time
- Failure rate (last 7 days)

### Task 7 — Wire controller routes

Replace all 501 stubs with actual handler implementations.

## Dev Notes

### Batch Generation Error Handling

If one pillar fails, the others should still generate. Use try/catch per pillar and record errors in `error_message` column with `status = 'failed'`.

### publish-now Endpoint

This endpoint sets status to `posting` and invokes the publisher service. If the publisher module (story 3.8) is not yet implemented, it should log a warning and set status to `approved` (ready for when publisher is available).

### Auto-Publish Logic

When `publish_enabled = true`:
- New posts go directly to `approved` status (skip `ready`)
- The scheduler (story 3.9) handles actual publishing at the scheduled time
