## Story

**As an** admin,
**I want** the batch generation API to accept an optional pillar override,
**so that** I can generate content for any pillar regardless of the weekly cadence.

---

## Acceptance Criteria

- [ ] **AC1** — `POST /api/forge-shadowfeed/generate-batch` accepts optional JSON body `{ "pillarId": "<PillarId>" }`
- [ ] **AC2** — When `pillarId` is provided and valid (exists in `PILLARS` array), that pillar is used for generation instead of cadence
- [ ] **AC3** — When `pillarId` is omitted, `undefined`, or empty string, cadence-based selection is used (existing behavior, zero regression)
- [ ] **AC4** — When `pillarId` is invalid (not in PILLARS list), return HTTP 400 with `{ error: "Invalid pillarId: <value>. Valid: educational-value, wake-up-slap, brand-breakdown, proof-social, the-offer" }`
- [ ] **AC5** — Cadence history is still recorded for the generated post (even when pillar is overridden)
- [ ] **AC6** — All other pipeline steps (theme rotation, hook archetype, funnel tier, discovery, scheduling) work unchanged
- [ ] **AC7** — Existing scheduler calls (no body) continue to work without changes — zero regression
- [ ] **AC8** — `npm run typecheck` passes clean (no new errors)

### Current `generateBatch()` Flow (lines 303-360 in service)

```typescript
async generateBatch(): Promise<BatchGenerationResult> {
  const cadence = getTodayCadence();  // ← This determines the pillar
  // ... uses cadence.pillarId for generation
  const item = await this.generatePillar(cadence.pillarId);
  // ... records cadence history
}
```

**Change needed:** When `pillarId` is passed, use it instead of `cadence.pillarId`. Still call `getTodayCadence()` for the other cadence data (hook archetypes, funnel tier) OR build a synthetic cadence entry for the overridden pillar.

### Current Controller (lines 70-78)

```typescript
forgeShadowFeedController.post('/generate-batch', async (_req, res) => {
  try {
    const result = await forgeShadowFeedService.generateBatch();
    return res.json(result);
  } catch (error) {
    return res.status(500).json({ error: errMsg(error) });
  }
});
```

**Change needed:** Read `req.body?.pillarId`, validate, pass to service.

### Valid Pillar IDs (from `PILLARS` in `forge-shadowfeed.types.ts`)

```
'educational-value' | 'wake-up-slap' | 'brand-breakdown' | 'proof-social' | 'the-offer'
```

### Important: Existing `POST /generate/:pillarId` Endpoint

There is already a `POST /generate/:pillarId` endpoint (line 80-87 in controller) that calls `generatePillar()` directly. DO NOT use this — it bypasses cadence recording and batch result format. The change should extend `generateBatch()` to keep the full pipeline intact.
