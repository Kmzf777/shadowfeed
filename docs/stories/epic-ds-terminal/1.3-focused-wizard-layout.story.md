# Story 1.3 — Focused Wizard Layout

**Epic:** DS-TERMINAL — Design System v2.0

**Status:** Ready
**Priority:** High
**Complexity:** S (Small)
**PRD Reference:** `docs/prd/prd-design-system-v2.md` § FR-006

## Description

As a user going through the setup or post creation wizard, I should see a distraction-free, full-width interface without the app sidebar, so I can focus entirely on the task at hand.

Currently, both `/setup` and `/criar-post` render the full app sidebar alongside the wizard content. This creates navigation noise during flows that require full attention. This story creates a `FocusedLayout` component that wizards use instead.

## Tasks

### Task 1 — Create `FocusedLayout.tsx`

Create `web/src/components/FocusedLayout.tsx`:

```tsx
'use client';

import Image from 'next/image';
import Link from 'next/link';

interface FocusedLayoutProps {
  children: React.ReactNode;
  currentStep?: number;
  totalSteps?: number;
}

export function FocusedLayout({ children, currentStep, totalSteps }: FocusedLayoutProps) {
  const progress = currentStep && totalSteps ? (currentStep / totalSteps) * 100 : 0;

  return (
    <div className="min-h-screen bg-[#0d0d0d] relative z-[1]">
      {/* Top bar */}
      <div className="fixed top-0 left-0 right-0 z-10 px-6 py-4 flex items-center justify-between">
        <Link href="/" className="opacity-70 hover:opacity-100 transition-opacity">
          <Image src="/logo.png" alt="Shadowfeed" width={48} height={48} />
        </Link>
        {currentStep && totalSteps && (
          <span className="text-[#4a4a4a] text-xs font-mono">
            {currentStep}/{totalSteps}
          </span>
        )}
      </div>

      {/* Progress bar */}
      {currentStep && totalSteps && (
        <div className="fixed top-0 left-0 right-0 h-[3px] bg-[#1c1c1c] z-20">
          <div
            className="h-full bg-[#8a00c4] transition-all duration-300 ease-out"
            style={{ width: `${progress}%` }}
          />
        </div>
      )}

      {/* Content */}
      <div className="flex items-start justify-center min-h-screen pt-24 pb-12 px-4">
        <div className="w-full max-w-[560px]">
          {children}
        </div>
      </div>
    </div>
  );
}
```

### Task 2 — Integrate into `/setup/page.tsx`

Read `web/src/app/setup/page.tsx`. Find the root layout wrapper (currently wraps the full wizard). Replace the outer layout with `FocusedLayout`, passing `currentStep={step}` and `totalSteps={4}` (after Story 1.5 reduces steps to 4 — for now use `totalSteps={7}` until 1.5 is done).

The sidebar is injected via the root layout or a layout.tsx in the route. Check if `/setup` has its own `layout.tsx` — if not, it inherits the root layout which likely renders Sidebar. To suppress the sidebar for focused routes, one approach:

**Option A (preferred):** Create `web/src/app/setup/layout.tsx` that renders `children` WITHOUT the main app layout:
```tsx
// web/src/app/setup/layout.tsx
export default function SetupLayout({ children }: { children: React.ReactNode }) {
  return <>{children}</>;
}
```

Then in `setup/page.tsx`, wrap content with `<FocusedLayout>`.

**Option B:** Add a `noSidebar` prop to the root layout and detect route. (More complex — prefer Option A.)

### Task 3 — Integrate into `/criar-post/page.tsx`

Same pattern as Task 2. Create `web/src/app/criar-post/layout.tsx`:
```tsx
export default function CreatePostLayout({ children }: { children: React.ReactNode }) {
  return <>{children}</>;
}
```

Then verify that `criar-post/page.tsx` wraps its content with `FocusedLayout`.

**Note:** The route rename (`/criar-post` → `/create`) happens in Story 1.6. Do the layout integration here in the existing path.

## Dev Notes

- Understand how the current root layout injects Sidebar. Check `web/src/app/layout.tsx` — if Sidebar is rendered there unconditionally, the per-route `layout.tsx` approach (Option A) is the cleanest solution in Next.js App Router.
- `FocusedLayout` does NOT import or render `<Sidebar>` at all.
- The `body::after` watermark is global CSS — it renders behind everything automatically. No extra CSS needed inside FocusedLayout.
- The progress bar in FocusedLayout is `position: fixed; top: 0` — it's on top of the page, covering the very top edge. It is NOT a separate element inside the content flow.
