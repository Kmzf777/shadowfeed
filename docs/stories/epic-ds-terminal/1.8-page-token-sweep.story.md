## Description

As a user navigating through Shadowfeed, every page I visit should look consistent with the DS v2.0 terminal aesthetic: solid opaque surfaces, 3px borders, no blur, correct text colors, and logo watermark visible behind content.

This story applies the DS v2.0 token sweep to all remaining pages not yet covered by previous stories, ensuring full visual consistency across the entire app.

## Tasks

### Task 1 — Work through each page sequentially

For each page, follow this process:
1. Read the file
2. Identify all glassmorphism, wrong radius, wrong colors using the cheatsheet
3. Apply replacements
4. Verify in browser

**Order of execution (recommended):**
1. `/` (home — simplest)
2. `/login`
3. `/my-posts`
4. `/posts/[id]`
5. `/account`
6. `/account/billing`
7. `/account/upgrade`
8. `/shadowfeedadmin`

### Task 2 — Token migration cheatsheet (same as Story 1.2)

| Remove | Replace with |
|--------|-------------|
| `bg-white/5` | `bg-[#161616]` |
| `bg-white/10` | `bg-[#1c1c1c]` |
| `border-white/10` | `border-[#1e1e1e]` |
| `border-white/20` | `border-[#2a2a2a]` |
| `backdrop-blur-*` | remove |
| `rounded-lg` / `rounded-xl` | `rounded-[3px]` |
| `rounded-full` (badges/buttons) | `rounded-[3px]` |
| `text-white/65` | `text-[#808080]` |
| `text-white/40` | `text-[#4a4a4a]` |
| `shadow-[0_0_30px_rgba...]` | `shadow-sm` |

### Task 3 — Ensure every page wrapper has `z-index: 1`

Every page's outermost div needs `relative z-[1]` so content appears above `body::after` watermark. This is the most common thing to miss.

```tsx
// Pattern for every page:
<div className="relative z-[1] ...existing classes...">
  {/* page content */}
</div>
```

### Task 4 — Remove per-page logo watermarks

Some pages may render the logo individually as a background watermark. These must be removed since `body::after` now handles it globally. Search for patterns like:

```tsx
// Remove these patterns:
<Image src="/logo.png" className="opacity-20 fixed ..." ... />
// or:
<div style={{ backgroundImage: "url('/logo.png')", opacity: 0.2 }} className="fixed ..." />
```

### Task 5 — Badge standardization

All badges across all pages must follow the DS badge spec. Key rule: **never `rounded-full`**. Search for:
```
grep -r "rounded-full" web/src/app/ --include="*.tsx"
```
Audit each result: if it's a badge or button → change to `rounded-[3px]`. If it's an avatar → keep.

### Task 6 — Progress bars

All progress bars (token bars, plan bars, generation progress) must be:
- `h-[3px]` (or `h-[1.5px]` for sidebar token bar)
- `rounded-none` (flat terminal line)
- Track: `bg-[#1c1c1c]`
- Fill: `bg-[#8a00c4]` → `bg-[#fbbf24]` (>70%) → `bg-[#f87171]` (>90%)

## Dev Notes

- This is the largest story by file count. Work through pages methodically — don't try to do them all at once.
- The `/login` page likely has a separate `LoginForm.tsx` component — update both the page and the form component.
- `/account/billing` has 3 tabs (Last Uses, Analytics, Plan Details). Each tab may be a separate component or section. Apply DS tokens to all tabs.
- `/shadowfeedadmin` is less critical (internal tool) — apply only the high-impact changes: card backgrounds, borders, radius. Don't over-invest here.
- The bar chart in `/account/billing` (Analytics tab) — update the bars to `bg-[#8a00c4]`. Chart container → `bg-[#111111]`.
- The "Most Popular" badge/ring on the middle plan in `/account/upgrade` — change from a glow shadow to a solid `border-[#8a00c4]` border. No box-shadow glow needed.
