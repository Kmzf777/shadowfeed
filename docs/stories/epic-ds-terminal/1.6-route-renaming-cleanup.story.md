## Description

As a developer maintaining the codebase, I need all route names to be in English and semantically clear, so the codebase is consistent with the product's English language migration and navigation intent is obvious to any developer or user.

This story:
1. Renames 4 routes (directory renames + all internal reference updates)
2. Adds a 301 redirect for `/manual` → `/create`
3. Updates all navigation links across the app

## Tasks

### Task 1 — Inventory all hardcoded references

Search the entire codebase before renaming:

```bash
# Find all references to old routes
grep -r "criar-post\|my-account\|/manual" web/src/ --include="*.tsx" --include="*.ts" -l
```

Document every file that needs updating.

### Task 2 — Rename directories

Use git mv to preserve history:

```bash
# Rename criar-post → create
git mv "web/src/app/criar-post" "web/src/app/create"

# Create account directory and move nested routes
git mv "web/src/app/my-account" "web/src/app/account"
# (this moves plan/ and plans/ along with the parent)
# Then rename the nested dirs:
git mv "web/src/app/account/plan" "web/src/app/account/billing"
git mv "web/src/app/account/plans" "web/src/app/account/upgrade"
```

### Task 3 — Add `/manual` redirect in `next.config.*`

Find the Next.js config file (`next.config.js`, `next.config.ts`, or `next.config.mjs`):

```js
// Add to the config object:
async redirects() {
  return [
    {
      source: '/manual',
      destination: '/create',
      permanent: true, // 301
    },
  ];
},
```

### Task 4 — Update all internal navigation references

Files to update (based on inventory from Task 1):

**`web/src/components/Sidebar.tsx`:**
- `/criar-post` → `/create`
- `/my-account` → `/account`

**`web/src/app/account/page.tsx`** (previously `my-account/page.tsx`):
- All `router.push('/my-account/plan')` → `router.push('/account/billing')`
- All `<Link href="/my-account/plans">` → `<Link href="/account/upgrade">`
- Back arrows and breadcrumbs

**`web/src/app/account/billing/page.tsx`** (previously `my-account/plan/page.tsx`):
- Back arrow: `/my-account` → `/account`

**`web/src/app/account/upgrade/page.tsx`** (previously `my-account/plans/page.tsx`):
- Back arrow: `/my-account` → `/account`

**`web/src/app/create/page.tsx`** (previously `criar-post/page.tsx`):
- Any `router.push('/my-posts?generating=true')` — keep as-is (my-posts is not renamed)
- Remove any reference to `/manual`

**`web/src/hooks/useAuth.ts`** or **`web/src/contexts/AuthContext.tsx`**:
- Any redirect to `/my-account` → `/account`

**Any other pages with navigation to renamed routes** (check inventory from Task 1).

### Task 5 — Update `usePathname()` active detection

In `Sidebar.tsx`, the active route is detected via `usePathname()`. Update comparison strings:

```tsx
// Before:
const isActive = pathname === '/criar-post' || pathname.startsWith('/criar-post');
const isAccountActive = pathname.startsWith('/my-account');

// After:
const isActive = pathname === '/create' || pathname.startsWith('/create');
const isAccountActive = pathname.startsWith('/account');
```

### Task 6 — Handle `/manual` directory

Option A (clean): Delete `web/src/app/manual/` entirely since the redirect is in `next.config.*`.
Option B (safe): Rename to `web/src/app/manual/_disabled/` to keep as reference temporarily.

**Recommended: Option A** — delete the directory. The 301 redirect in next.config handles the route.

```bash
rm -rf "web/src/app/manual"
```

## Dev Notes

- **Do the search (Task 1) before any rename.** Missing a reference = 404 in production.
- `git mv` preserves git history. Using file system move (drag/drop) loses history. Use git.
- After renaming, Next.js App Router auto-generates routes from the directory structure. No routing config needed beyond the redirect.
- If `my-account/plan/` has a `page.tsx` and `my-account/plans/` has a `page.tsx`, after the rename to `account/billing/` and `account/upgrade/`, verify both are in the right paths.
- The `/my-posts` route is NOT renamed (it's already English and clear).
- The `/posts/[id]` route is NOT renamed.
- The `/shadowfeedadmin` route is NOT renamed (kept for security by obscurity).
- After renaming, run the dev server and navigate to each new route to verify.
