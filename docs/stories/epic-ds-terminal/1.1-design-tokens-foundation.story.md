# Story 1.1 — Design Tokens Foundation

**Epic:** DS-TERMINAL — Design System v2.0
**Story ID:** DS-01
**Status:** Ready for Review
**Priority:** Critical — blocks all other stories
**Complexity:** M (Medium)
**PRD Reference:** `docs/prd/prd-design-system-v2.md` § FR-001, FR-002, FR-003, FR-005

---

## Description

As a developer implementing the design system, I need a single source of truth for all visual tokens in `globals.css` so that every component in the app uses the same solid, opaque, terminal-aesthetic design language consistently.

The current `globals.css` has rgba-based borders and backgrounds (glassmorphism), inconsistent border-radius values (3px, 8px, 12px), and unused variables. This story completely replaces the token section with the DS v2.0 token system.

**This story is Wave 1 — it must be completed before any other DS story begins.**

## Dev Notes

- `body::after` (watermark) uses `z-index: 0`. All page content wrappers need `position: relative; z-index: 1` or higher to appear above it. This will be handled story by story in DS-08.
- `body::before` (scanlines) uses `z-index: 9999` so it renders on top of all content. The `pointer-events: none` ensures no click interference.
- Do NOT touch `.design-slide` or `.design-slide *` — these have intentional font isolation for the post renderer.
- `Inter` and `Inter_Tight` are loaded in `layout.tsx` — they are used by `.design-slide` (slide renderer). Do NOT remove them from layout.tsx. They just shouldn't be in the `* {}` global font override rule (they already aren't).
- `--accent-glow: rgba(138, 0, 196, 0.25)` is the ONLY rgba value allowed to remain. It's used exclusively in `--shadow-cta`.
