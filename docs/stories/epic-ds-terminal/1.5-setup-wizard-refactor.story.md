# Story 1.5 — Setup Wizard Refactor (7 → 4 Steps)

**Epic:** DS-TERMINAL — Design System v2.0
**Story ID:** DS-05
**Status:** Ready
**Priority:** High
**Complexity:** L (Large)
**PRD Reference:** `docs/prd/prd-design-system-v2.md` § FR-007, § 7.3
**Blocked by:** Story 1.1 (tokens), Story 1.3 (FocusedLayout)

## Description

As a new user completing onboarding, I want a streamlined 4-step setup process instead of the current 7 steps, so I can start using the product faster without excessive friction before seeing any value.

The wizard is also visually updated: terminal-style labels, step slide animations, flat progress bar, and a glitch-flicker on the logo on final submission.

### Task 7 — Final submit with glitch effect

```tsx
const handleSubmit = async () => {
  setIsSubmitting(true);
  setShowGlitch(true); // triggers .glitch-flicker on logo via state

  try {
    await supabase
      .from('users')
      .update({
        display_name: formData.display_name,
        instagram_username: formData.instagram_username,
        target_audience: formData.target_audience,
        main_pain_point: formData.main_pain_point,
        voice_tone: formData.voice_tone,
        user_prompt: formData.user_prompt,
        highlight_color: '#8a00c4', // default — picker removed from wizard
        setup_completed: true,
      })
      .eq('id', user.id);

    // Wait for glitch animation (600ms) then redirect
    setTimeout(() => router.replace('/'), 600);
  } catch (error) {
    setIsSubmitting(false);
    setShowGlitch(false);
  }
};
```

Logo element in FocusedLayout top-left (or a floating logo inside the setup page) gets `className={showGlitch ? 'glitch-flicker' : ''}`.

## Dev Notes

- The `highlight_color` field still exists in the database. Hardcode it to `#8a00c4` in the submit payload. A separate ticket can add color picking to `/account` settings later.
- When implementing step transitions: the key challenge is that React renders declaratively. Use a `key` prop on the step wrapper to trigger remount + animation:
  ```tsx
  <div key={step} className="step-enter">
    {/* step content */}
  </div>
  ```
  This causes React to unmount/remount when `step` changes, triggering the CSS animation.
- The `step-exit` animation is harder to implement purely in CSS since React removes the element before the animation completes. If step-exit animation is complex to implement, skip it — `step-enter` alone is sufficient for the UX goal.
- Current voice_tone values (from existing Step 5): `professional`, `friendly`, `provocative`, `inspirational`, `humorous` — keep these exact values, only change styling.
