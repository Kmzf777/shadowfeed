## Description

As a **Recon Ultra pipeline**, I need to generate search queries dynamically from the user's profile fields and the selected pillar's `queryAngles`, so that all source adapters fetch content relevant to the user's niche instead of hardcoded AI keywords.

---

## Acceptance Criteria

- [x] **AC1** — `recon-query-builder.ts` exports `generateReconQueries(userId, pillarId)` that returns `string[]`
- [x] **AC2** — Queries are generated using Gemini 2.5 Flash via existing `src/config/gemini.ts` configuration
- [x] **AC3** — The Gemini prompt consumes these V2 profile fields: `niche`, `target_audience`, `audience_frustration`, `audience_desire`, `expertise_statement`, `content_pillars[]`, `avoid_topics`
- [x] **AC4** — Falls back to V1 fields (`target_audience`, `main_pain_point`, `user_prompt`) when V2 fields unavailable
- [x] **AC5** — Generates exactly `pillarConfig.queryAngles.length` queries (3-7 depending on pillar)
- [x] **AC6** — Each query is <= 10 words, English only, no quotes
- [x] **AC7** — Each query maps to one `queryAngle` from the pillar config
- [x] **AC8** — Queries do NOT contain terms from `avoid_topics`
- [x] **AC9** — On Gemini error, falls back to 3 hardcoded queries built from `niche + queryAngles[0..2]`
- [x] **AC10** — Query cache: checks `sf_recon_query_cache` before calling Gemini. On cache hit (same `profile_hash`, not expired), returns cached queries
- [x] **AC11** — Cache invalidation: `profile_hash` is SHA-256 of `niche + target_audience + audience_frustration + audience_desire + content_pillars.join(',')`
- [x] **AC12** — Cache TTL: 24 hours from generation time
- [x] **AC13** — When cache miss, stores generated queries with `profile_hash` in `sf_recon_query_cache` (upsert on user_id+pillar_id)

## Tasks

### Task 1 — Implement `generateReconQueries()`

Core function signature:
```typescript
export async function generateReconQueries(
  userId: string,
  pillarId: PillarId
): Promise<string[]>
```

Steps:
1. Load user profile from `users` table
2. Determine V2 vs V1 fields (same logic as `forge-smart.service.ts:27-59`)
3. Compute `profile_hash` from key fields
4. Check `sf_recon_query_cache` for valid cache entry
5. If cache hit → return `queries` from cache
6. If cache miss → call Gemini with pillar-aware prompt
7. Validate output with Zod schema
8. Store in cache (upsert)
9. Return queries

### Task 2 — Build Gemini prompt

Follow the pattern from `smart-query-generator.ts` but enhanced:

**System prompt template:**
```
You are a content research query generator for a {niche} professional.
Target audience: {target_audience}
Their main frustration: {audience_frustration}
Their desire: {audience_desire}
Expert positioning: {expertise_statement}

Generate exactly {N} search queries for finding {pillar.name} content.
Each query must target one of these angles: {pillar.queryAngles.join(', ')}

RULES:
- Max 10 words per query
- English only
- No quotes or special characters
- Prefer queries that return data-rich, actionable content
- Avoid: press releases, product announcements
- NEVER include: {avoid_topics}

Return JSON: { "queries": ["query1", "query2", ...] }
```

### Task 3 — Implement profile hash computation

```typescript
import { createHash } from 'crypto';

function computeProfileHash(profile: UserProfile): string {
  const key = [
    profile.niche ?? '',
    profile.target_audience ?? '',
    profile.audience_frustration ?? '',
    profile.audience_desire ?? '',
    (profile.content_pillars ?? []).join(','),
  ].join('|');
  return createHash('sha256').update(key).digest('hex');
}
```

### Task 4 — Implement cache check/store

```typescript
async function getCachedQueries(userId: string, pillarId: string, profileHash: string): Promise<string[] | null>
async function cacheQueries(userId: string, pillarId: string, queries: string[], profileHash: string): Promise<void>
```

Use Supabase upsert on `(user_id, pillar_id)` constraint.

### Task 5 — Write unit tests

Test cases:
1. V2 profile generates queries using niche + audience fields
2. V1 profile fallback generates queries using target_audience + main_pain_point
3. Cache hit returns cached queries without Gemini call
4. Profile change (different hash) triggers new Gemini call
5. Gemini error returns fallback queries
6. `avoid_topics` terms not present in generated queries
7. Output respects query count = queryAngles.length

### Cache Upsert Pattern
```sql
INSERT INTO sf_recon_query_cache (user_id, pillar_id, queries, profile_hash, expires_at)
VALUES ($1, $2, $3, $4, NOW() + INTERVAL '24 hours')
ON CONFLICT (user_id, pillar_id)
DO UPDATE SET queries = $3, profile_hash = $4, expires_at = NOW() + INTERVAL '24 hours';
```
