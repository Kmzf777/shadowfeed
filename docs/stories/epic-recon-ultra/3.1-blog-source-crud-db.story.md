## Description

As a **ShadowFeed user**, I want to manage a list of blog URLs I follow, so that the Recon Ultra system can scrape articles from my preferred blogs for content inspiration.

---

## Acceptance Criteria

- [x] **AC1** — `POST /api/recon-ultra/blog-sources` adds a blog URL for the authenticated user
- [x] **AC2** — Request body: `{ blog_url: string, blog_name?: string, scrape_frequency?: 'hourly'|'daily'|'weekly' }`
- [x] **AC3** — Validation: URL must be valid HTTPS, returns HTTP 200 on HEAD request
- [x] **AC4** — Validation: rejects social media URLs (twitter.com, x.com, reddit.com, instagram.com, tiktok.com, facebook.com, linkedin.com)
- [x] **AC5** — Validation: rejects private IPs and localhost (SSRF prevention)
- [x] **AC6** — Max 10 blog sources per user enforced (returns 400 if exceeded)
- [x] **AC7** — Duplicate `(user_id, blog_url)` returns 409 Conflict
- [x] **AC8** — `GET /api/recon-ultra/blog-sources` returns user's blog sources sorted by `created_at DESC`
- [x] **AC9** — `DELETE /api/recon-ultra/blog-sources/:id` removes a blog source (only own sources)
- [x] **AC10** — `PATCH /api/recon-ultra/blog-sources/:id` toggles `is_active` field
- [x] **AC11** — All endpoints require authenticated user (userId from auth context)

## Dev Notes

### Auth Context
Get `userId` from request context. Follow the same auth middleware pattern used in other controllers (check `recon.controller.ts` or `forge-smart.controller.ts` for the pattern).

### Head Request Timeout
Set timeout for HEAD validation to 5 seconds. Don't block user on slow blogs — if HEAD fails, still allow adding with a warning.
