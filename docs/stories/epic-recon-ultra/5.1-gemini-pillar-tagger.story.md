### Task 2 — Implement in-memory LRU cache ✅

```typescript
class PillarClassificationCache {
  private cache = new Map<string, { scores: PillarScores; timestamp: number }>();
  private readonly maxSize = 500;
  private readonly ttlMs = 72 * 60 * 60 * 1000; // 72h

  get(url: string): PillarScores | null {
    const entry = this.cache.get(url);
    if (!entry) return null;
    if (Date.now() - entry.timestamp > this.ttlMs) {
      this.cache.delete(url);
      return null;
    }
    return entry.scores;
  }

  set(url: string, scores: PillarScores): void {
    if (this.cache.size >= this.maxSize) {
      // Delete oldest entry (LRU)
      const oldest = this.cache.keys().next().value;
      if (oldest) this.cache.delete(oldest);
    }
    this.cache.set(url, { scores, timestamp: Date.now() });
  }
}
```

### Task 3 — Implement daily rate limiter ✅

```typescript
class DailyGeminiLimiter {
  private counts = new Map<string, { count: number; date: string }>();
  private readonly maxPerDay = 5;

  canCall(userId: string): boolean {
    const today = new Date().toISOString().slice(0, 10);
    const entry = this.counts.get(userId);
    if (!entry || entry.date !== today) return true;
    return entry.count < this.maxPerDay;
  }

  record(userId: string): void {
    const today = new Date().toISOString().slice(0, 10);
    const entry = this.counts.get(userId);
    if (!entry || entry.date !== today) {
      this.counts.set(userId, { count: 1, date: today });
    } else {
      entry.count++;
    }
  }
}
```

export function getPillarTag(scores: PillarScores): PillarId {

## Dev Notes

### Why In-Memory Cache?
The pillar classification is called during scoring, which happens frequently. A DB cache would add latency. In-memory LRU with 72h TTL and 500-entry cap is lightweight and fast. On server restart, cache is lost — this is acceptable since it's just an optimization.

### Cost Control
At max 5 Gemini calls/user/day for classification, with 100 users that's 500 calls/day. Gemini 2.5 Flash is cheap for short prompts (~100 tokens input). This is well within budget.

### Scoring Impact
Adding 0.15 weight for pillar alignment means the other 4 weights sum to ~0.85 instead of 1.0. This is intentional — alignment is a bonus signal, not a replacement for the core dimensions.
