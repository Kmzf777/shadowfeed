## Description

## Tasks

### Task 1 — Implement Stage 0 cache lookup

Add to `forge-smart.service.ts` before Stage 1:

```typescript
// ── Stage 0: Cache Lookup ──────────────────────────────────
logger.info({ userId, pillarId }, '[FORGE-SMART] Stage 0 — checking recon cache');

let cachedCandidates: SmartCandidate[] | null = null;
let generationSource: 'cache' | 'live' = 'live';

try {
  const { data: cached } = await supabase
    .from('sf_intel_sources_v2')
    .select('*')
    .eq('user_id', userId)
    .eq('pillar_tag', pillarConfig.id)
    .eq('used', false)
    .gt('expires_at', new Date().toISOString())
    .order('final_score', { ascending: false })
    .limit(10);

  if (cached && cached.length >= 3 && cached[0].final_score >= 7.0) {
    cachedCandidates = mapIntelToSmartCandidates(cached);
    generationSource = 'cache';
    logger.info({ userId, count: cached.length, topScore: cached[0].final_score },
      '[FORGE-SMART] Stage 0 — CACHE HIT');
  }
} catch (err) {
  logger.warn({ error: (err as Error).message }, '[FORGE-SMART] Stage 0 — cache lookup failed, falling back to live');
}
```

### Task 2 — Implement cache-to-SmartCandidate mapper

```typescript
function mapIntelToSmartCandidates(intelItems: any[]): SmartCandidate[] {
  return intelItems.map(item => ({
    source_type: item.source_type,
    title: item.title,
    summary: item.summary ?? item.body_content?.slice(0, 500) ?? null,
    url: item.url,
    author: item.author,
    source_score: item.source_score ? Number(item.source_score) : null,
    source_comments: item.source_comments,
    posted_at: item.posted_at,
    relevance_score: Number(item.relevance_score),
    query_used: item.query_used ?? 'recon-cache',
    scraped_body: item.body_content,
  }));
}
```

### Task 3 — Implement write-back on cache miss

After Stage 3 scoring, if `generationSource === 'live'`, save all candidates:

```typescript
if (generationSource === 'live' && scored.length > 0) {
  await writeBackToReconCache(userId, pillarConfig.id, scored);
}

async function writeBackToReconCache(userId: string, pillarId: string, candidates: SmartCandidateScored[]): Promise<void> {
  const items = candidates.slice(0, 20).map(c => ({
    user_id: userId,
    source_type: c.source_type,
    pillar_tag: pillarId,
    title: c.title,
    summary: c.summary,
    body_content: c.scraped_body ?? null,
    url: c.url,
    author: c.author,
    relevance_score: c.relevance_score,
    final_score: c.final_score,
    query_used: c.query_used,
    posted_at: c.posted_at,
    expires_at: computeTtl(c.source_type),
  }));

  await supabase.from('sf_intel_sources_v2')
    .upsert(items, { onConflict: 'user_id,url', ignoreDuplicates: false });
}
```

## Dev Notes

### Minimal Changes to Existing Flow
The goal is to add Stage 0 as a pure optimization layer. If anything goes wrong with cache, the system falls back to the existing live-fetch pipeline. Zero changes to Stages 1-4 behavior.

### Pipeline Flow After Change
```
Stage 0: Cache check (NEW)
  ├─ CACHE HIT → candidates ready → Stage 3
  └─ CACHE MISS → Stage 1 → Stage 2 → Stage 2.5 → Stage 3 → Write-back (NEW)
Stage 4: Generation (unchanged)
```

### IntelItem-to-SmartCandidate Mapping
The `sf_intel_sources_v2` schema has more fields than `SmartCandidate`. The mapper selects only the fields needed by the scorer. `body_content` maps to `scraped_body`.
