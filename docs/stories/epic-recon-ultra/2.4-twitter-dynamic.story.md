## Description

As a **Recon Ultra pipeline**, I need a Twitter source that uses profile-derived queries via TwitterAPI.io instead of hardcoded env search queries and profiles, so that Twitter content is relevant to the user's niche.

---

## Acceptance Criteria

- [x] **AC1** — `twitter-dynamic.source.ts` exports `fetchTwitterDynamic(queries: string[]): Promise<ReconUltraCandidate[]>`
- [x] **AC2** — Uses TwitterAPI.io advanced search (same as `smart-content-fetcher.ts` pattern)
- [x] **AC3** — Each query appended with `-is:retweet lang:en`, queryType `Top`
- [x] **AC4** — Filter: `likeCount >= 20 OR retweetCount >= 5`
- [x] **AC5** — Max 5 tweets per query
- [x] **AC6** — Thread enrichment: if `conversationId !== tweet.id`, fetches full thread
- [x] **AC7** — `env.TWITTER_SEARCH_QUERIES` and `env.TWITTER_PROFILES` are NOT used
- [x] **AC8** — Returns `ReconUltraCandidate[]` with `source_type: 'twitter'`
- [x] **AC9** — `engagement_score` pre-computed as `likes + (retweets × 2)` stored in `source_score`
- [x] **AC10** — Graceful skip if `env.TWITTERAPI_IO_KEY` not configured
- [x] **AC11** — Each query runs with error isolation

## Dev Notes

### Difference from Current `twitter.source.ts`
| Current (Playwright-based) | New (API-based) |
|---------------------------|-----------------|
| Playwright browser scraping | TwitterAPI.io HTTP API |
| `env.TWITTER_PROFILES` + `env.TWITTER_SEARCH_QUERIES` | Profile-derived queries only |
| Complex DOM parsing | Clean JSON response |

### Reuse from Forge-Smart
The implementation is nearly identical to `smart-content-fetcher.ts:fetchTwitterByQuery()`. Key differences:
- Returns `ReconUltraCandidate[]` instead of `SmartCandidate[]`
- Queries come from Recon Ultra query builder, not Forge-Smart
