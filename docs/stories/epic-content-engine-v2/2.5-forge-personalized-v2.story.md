# Story 2.5 — Forge Personalized v2 (Content Type Routing)

**Epic:** CONTENT-ENGINE-V2 — Content Engine v2.0
**Story ID:** CE-05
**Status:** Draft
**Priority:** P1 — depends on Stories 2.2 and 2.3
**Complexity:** M (Medium)
**PRD Reference:** `docs/prd-content-engine-v2.md` § 4.2, § 8.2, § 14

---

## Description

As a developer, I need `forge-personalized.service.ts` updated to accept a `contentType` and `depthPreference` parameter and route the generation through the new modular prompt builder so that each post is generated with the correct specialized prompt, depth range, and narrative template for the selected content type.

The current service ignores content type entirely and uses a single generic prompt. This story wires the new prompt builder into the service and updates the types to carry `contentType` and `depth` through the generation pipeline.

**Depends on:** Story 2.2 (`ContentTypeId`, `ContentDepth` types), Story 2.3 (modular prompt builder)
**Unblocks:** Story 2.7 (frontend that calls this service)

---

### Task 2 — Update `forge-personalized.service.ts`: read new params

Read the existing service to understand current flow. Then:

1. Extract `contentType` and `depthPreference` from request body with defaults
2. Fetch user profile including all new strategic fields from Supabase:
   ```typescript
   const { data: profile } = await supabase
     .from('users')
     .select(`
       target_audience, main_pain_point, voice_tone, user_prompt,
       niche, expertise_statement, transformation_before, transformation_after,
   ```

   ```typescript

     return res.status(400).json({ error: 'Sales content type requires an offer configured in your profile.' });
   }
   ```

### Task 3 — Wire new prompt builder

Replace the current `buildPrompt(...)` call with:

```typescript

const { systemPrompt, userPrompt } = buildForgePrompt({

  userProfile: profile,

```

Pass `systemPrompt` as the OpenAI system message and `userPrompt` as the user message.

## Dev Notes

### Existing Service Flow

Read `src/modules/forge-personalized/forge-personalized.service.ts` fully before modifying. The current flow likely:
1. Validates request
2. Fetches user profile
3. Calls prompt builder
4. Calls OpenAI
5. Validates JSON response (Zod)
6. Saves to `sf_posts`
7. Returns post

This story modifies steps 2, 3, 4 (max_tokens), and 6 (save content_type/depth).

### Profile Fallbacks for Legacy Users

Legacy users have `niche = null`, `expertise_statement = null`, etc. The prompt builder (Story 2.3) handles these with fallbacks. The service just needs to pass the profile — don't block if new fields are null.

### Product Context Construction

When `contentType === 'sales'`, build `product` context from the first `is_primary: true` offer, or from the first offer in the array:
```typescript
const primaryOffer = profile.offers?.find(o => o.is_primary) ?? profile.offers?.[0];
const product = primaryOffer ? {
  enabled: true,
  name: primaryOffer.name,
  mainBenefit: primaryOffer.main_benefit,
  ctaKeyword: primaryOffer.cta_keyword,
  purchaseMethod: primaryOffer.purchase_method,
} : { enabled: false };
```
