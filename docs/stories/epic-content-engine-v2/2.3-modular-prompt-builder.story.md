# Story 2.3 — Modular Prompt Builder (7 Specialized Prompt Modules)

**Epic:** CONTENT-ENGINE-V2 — Content Engine v2.0
**Story ID:** CE-03
**Status:** Draft
**Priority:** P0 — can run in parallel with Story 2.4
**Complexity:** L (Large)
**PRD Reference:** `docs/prd-content-engine-v2.md` § 8

---

## Description

As a developer building the content engine, I need the monolithic `prompt-builder.ts` refactored into a modular architecture with one prompt module per content type so that each of the 7 content types receives a specialized system prompt, depth block, narrative block, and few-shot example instead of a single generic prompt.

The current `prompt-builder.ts` generates one generic prompt regardless of content intent. This story:
1. Creates `src/modules/forge-personalized/prompts/` directory with 8 files (base + 7 type modules)
2. Refactors `prompt-builder.ts` as an orchestrator that routes to the correct module
3. Adds `buildDepthBlock` and `buildNarrativeBlock` helpers

**Depends on:** Story 2.2 (needs `ContentTypeConfig`, `ContentDepth`, `ContentTypeId` types)
**Parallel with:** Story 2.4 (Setup Wizard)

- [ ] **AC4** — `base.prompt.ts` exports shared block builders: `buildDateBlock()`, `buildProfileBlock(userProfile)`, `buildDepthBlock(depth, contentType)`, `buildNarrativeBlock(contentType, depth)`, `buildSourceBlock(source)`, `buildProductBlock(product)`, `buildOutputInstructions()`
- [ ] **AC5** — `buildDepthBlock` includes the range from `ContentTypeConfig.slideCountRange` for the given depth, plus the AI decision rules from PRD §8.3

- [ ] **AC9** — When `ctx.contentType` is not recognized, falls through to a safe generic fallback (or throws with clear message)
- [ ] **AC10** — `npm run typecheck` and `npm run lint` pass after all changes

### Task 1 — Create `prompts/` directory and `base.prompt.ts`

Create `src/modules/forge-personalized/prompts/base.prompt.ts`:

Implement these exported functions:

- `buildOutputInstructions()` — final instructions for JSON output format

### Task 2 — Create the 7 prompt modules

Create each file in `src/modules/forge-personalized/prompts/`:

**`educational.prompt.ts`** — Uses the Educational system prompt from PRD §6.1 TYPE 1. Key rules: standalone value per slide, open curiosity loop on hook, concrete data (%, studies), applicable insights, min 400 chars body_markdown on content slides.

**`tutorial.prompt.ts`** — Uses Tutorial system prompt from PRD §6.1 TYPE 2. Key rules: 100% actionable steps, hiper-specific (tools, times, quantities), anticipate errors, numbered steps, 300–600 chars body_markdown.

**`sales.prompt.ts`** — Uses Sales/AIDA system prompt from PRD §6.1 TYPE 3. Key rules: never mention price, one benefit per slide, 'você' throughout, keyword in bold `**[PALAVRA]**`, 200–500 chars. Requires product data.

**`authority.prompt.ts`** — Uses Authority system prompt from PRD §6.1 TYPE 4. Key rules: unique-experience perspective, counter mainstream when justified, 400–700 chars, expert-sharing tone (not preaching).

**`story.prompt.ts`** — Uses Storytelling system prompt from PRD §6.1 TYPE 5. Key rules: fictional names but plausible, complete arc (situation→conflict→decision→result), lesson emerges naturally, 250–500 chars.

**`list.prompt.ts`** — Uses List/Curation system prompt from PRD §6.1 TYPE 6. Key rules: item name + why it's on the list, at least 1 surprise item, organized by relevance, number in hook, 150–350 chars per item.

**`controversy.prompt.ts`** — Uses Controversy system prompt from PRD §6.1 TYPE 7. Key rules: argumentatively solid not just provocative, acknowledge opposing side, never attack people by name, 300–600 chars, secure argumentative tone.

### Task 3 — Refactor `prompt-builder.ts` as orchestrator

Update `src/modules/forge-personalized/prompt-builder.ts`:

```typescript
import type { ContentTypeId, ContentDepth } from '../../shared/types/content-types.types';
import * as educational from './prompts/educational.prompt';
import * as tutorial from './prompts/tutorial.prompt';
import * as sales from './prompts/sales.prompt';
import * as authority from './prompts/authority.prompt';
import * as story from './prompts/story.prompt';
import * as list from './prompts/list.prompt';
import * as controversy from './prompts/controversy.prompt';
import {
  buildDateBlock, buildProfileBlock, buildDepthBlock,
  buildNarrativeBlock, buildSourceBlock, buildProductBlock,
  buildOutputInstructions
} from './prompts/base.prompt';

const MODULE_MAP = {
  educational, tutorial, sales, authority, story, list, controversy,
} as const;

export interface PromptBuildResult {
  systemPrompt: string;
  userPrompt: string;
}

export function buildForgePrompt(ctx: PersonalizedForgeContext): PromptBuildResult {
  const { contentType, depth, userProfile, source, product } = ctx;

  if (contentType === 'sales' && !product?.enabled) {
    throw new Error('[PROMPT-BUILDER] Sales content type requires offer configuration');
  }

  const module = MODULE_MAP[contentType] ?? MODULE_MAP.educational; // safe fallback

  const systemPrompt = module.buildSystemPrompt(userProfile);

  const userPrompt = [
    buildDateBlock(),
    buildProfileBlock(userProfile),
    buildDepthBlock(depth, contentType),
    buildSourceBlock(source),
    product?.enabled ? buildProductBlock(product) : '',
    buildNarrativeBlock(contentType, depth),
    module.buildRulesBlock(depth),
    module.getFewShotExample(depth),
    buildOutputInstructions(),
  ].filter(Boolean).join('\n\n');

  return { systemPrompt, userPrompt };
}
```

Update `PersonalizedForgeContext` type in `forge-personalized.types.ts` to include `contentType: ContentTypeId` and `depth: ContentDepth` (see Story 2.5 for the full types update — coordinate interface changes).

## Dev Notes

### Current `prompt-builder.ts`

The existing file at `src/modules/forge-personalized/prompt-builder.ts` currently takes some context and returns a single prompt string. Read the existing implementation before modifying to understand current parameters and callers.

### Few-Shot Size Constraint

Per PRD §16: few-shot examples must stay under 800 tokens. Keep them compact: 2–3 slides max in the example JSON, not a full carousel.

### Profile Fallback for Legacy Users

When a new profile field like `niche` is null (legacy user), fall back gracefully:
- `niche ?? target_audience`
- `expertise_statement ?? user_prompt`
- `audience_frustration ?? main_pain_point`

### `PersonalizedForgeContext` Interface Coordination

Story 2.5 will finalize the full `PersonalizedForgeContext` type. For this story, define a local interface or extend the existing type. Coordinate with Story 2.5 to avoid conflicts.
