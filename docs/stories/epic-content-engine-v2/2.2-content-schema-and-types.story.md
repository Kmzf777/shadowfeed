# Story 2.2 — Content Schema & Types Foundation

**Epic:** CONTENT-ENGINE-V2 — Content Engine v2.0
**Story ID:** CE-02
**Status:** Draft
**Priority:** P0 Critical — blocks forge personalized, forge smart, and frontend stories
**Complexity:** M (Medium)

## Description

As a developer building the content engine, I need a centralized TypeScript type system for the 7 content types and an updated Zod schema that accepts 4–20 slides with all new roles so that the forge engine can validate, generate, and route content correctly by type.

Currently `content-schema.ts` hardcodes a max of 15 slides and only includes basic roles (`hook`, `cta`, `content`). This story:
1. Creates `src/shared/types/content-types.types.ts` — the canonical definition of all 7 content types, their narrative templates, slide ranges, and configuration
2. Updates `src/shared/schemas/content-schema.ts` — expands slide range to 4–20, adds `UniversalRoleEnum` with all new roles, and adds `content_type` / `depth_level` fields to the carousel schema
3. Updates `src/shared/schemas/content-validator.ts` — adds depth-range validation per content type

**Depends on:** Story 2.1 (DB migration must exist, but no runtime dependency for this TypeScript work)

### Task 1 — Create `content-types.types.ts`

Create `src/shared/types/content-types.types.ts` with the full type definitions and `CONTENT_TYPES` array as specified in PRD §6.2.

Key items:

- Export `GOAL_DISTRIBUTIONS` (the weighted distribution map from PRD §9.1 — used by rotation logic in Story 2.6)

```typescript
export type ContentTypeId =
  | 'educational' | 'tutorial' | 'sales'
  | 'authority' | 'story' | 'list' | 'controversy';

export type ContentDepth = 'shallow' | 'balanced' | 'dense';
export type CtaStyle = 'engagement' | 'product' | 'follow' | 'debate';
export type PrimaryGoal =
  | 'grow_audience' | 'generate_leads' | 'direct_sales'
  | 'build_authority' | 'balanced';

// ... (full interfaces as per PRD §6.2)

export const CONTENT_TYPES: ContentTypeConfig[] = [ /* 7 types */ ];

export function getContentType(id: ContentTypeId): ContentTypeConfig {
  const type = CONTENT_TYPES.find(t => t.id === id);
  if (!type) throw new Error(`[CONTENT-TYPES] Unknown content type: ${id}`);
  return type;
}
```

### Task 3 — Update `content-validator.ts`

Add to `src/shared/schemas/content-validator.ts`:

```typescript
import { getContentType } from '../types/content-types.types';
import type { ContentDepth, ContentTypeId } from '../types/content-types.types';
import { logger } from '../utils/logger'; // existing logger

export function validateDepthRange(
  slides: number,
  depth: ContentDepth,
  contentType: ContentTypeId
): void {
  const type = getContentType(contentType);
  const range = type.slideCountRange[depth];
  if (!range) return; // type doesn't support this depth

  if (slides < range.min) {
    logger.warn(
      { slides, expected_min: range.min, depth, contentType },
      '[CONTENT-VALIDATOR] Slide count below minimum for depth'
    );
    return; // warning only — AI may have had sparse input
  }

  if (slides > range.max) {
    throw new Error(
      `[CONTENT-VALIDATOR] Slide count ${slides} exceeds max ${range.max} for ${contentType}/${depth}`
    );
  }
}
```
